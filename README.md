# Отпуска

Учёт отпусков сотрудников: приложение для macOS и Windows с собственной локальной базой.
Заменяет книгу Excel «Отпуска.xlsx» — те же вкладки и те же правила расчёта, но данные вводятся
прямо в программе, а остатки, крайние сроки и подсветка «горящих» отпусков считаются сами.

Вкладки: **Сводка** · **Сотрудники** · **Периоды** · **Журнал отпусков** · **График отпусков** · **Напоминания** ·
**Отчёты** · **Настройки**.

**Виды отпусков.** Кроме ежегодного оплачиваемого, в журнал вносятся отпуск без сохранения заработной платы,
по беременности и родам и по уходу за ребёнком. Отпуск без оплаты свыше 14 календарных дней в рабочем году
и отпуск по уходу за ребёнком не идут в стаж (ст. 121 ТК РФ): окончание рабочего года переносится на эти дни,
а следующий год считается со дня после него. Декретный отпуск идёт в стаж. Продлённые годы видны в «Периодах» и в карточке.

**График отпусков и напоминания.** График на год сверяется с журналом («По графику», «Оформлен», «В отпуске»,
«Использован», «Не оформлен»). За 14 дней и за 1 месяц до начала отпуска, а также за 14 дней до окончания декретного
отпуска и отпуска по уходу за ребёнком программа показывает карточки сотрудников на вкладке «Напоминания»
(переключатель сроков сверху), число напоминаний — у вкладки и на «Сводке».

**Несколько баз — по одной на организацию.** При запуске программа спрашивает, в какую базу войти (это можно выключить).
Название открытой базы всегда видно в левом верхнем углу; нажатие на эту кнопку открывает список организаций —
выбрали, и программа сразу переключилась на другую базу, без возврата на экран выбора. Там же «Новая организация…» и
«Окно выбора базы». Если в карточке сотрудника или в «Настройках» есть несохранённые изменения, программа не даст
переключиться и скажет об этом. Переименование и удаление баз — «Настройки» → «Базы данных».

## Данные

Каждая база — отдельный файл SQLite `otpuska.db` в своей папке:

| ОС | Где лежит |
|----|-----------|
| macOS | `~/Library/Application Support/Otpuska/` |
| Windows | `%LOCALAPPDATA%\Otpuska\` |

```
Otpuska/
  config.json              список баз и их названия, тема, масштаб
  otpuska.db               база версии 1.0 («Основная база») — осталась на своём месте
  backups/                 её ежедневные копии (хранятся 14 последних) и копии «до обновления»
  databases/<номер>/       каждая новая база: otpuska.db и backups/
  deleted/                 удалённые базы — 30 дней, потом стираются
```

`OTPUSKA_HOME` переопределяет папку. Резервную копию открытой базы можно сделать и восстановить в «Настройках».

**Обновление с 1.0 и 1.1.** Базу не нужно переносить вручную: при первом запуске новой версии тот же файл
`otpuska.db` записывается в список под названием «Основная база» (переименуйте в «Настройках»). Пока в списке одна
база, она открывается сразу, без вопросов. Перед обновлением файла до схемы 2 (виды отпусков, график) в `backups/`
сохраняются копии в старом формате: `otpuska-before-update-…db` и `otpuska-before-v2-…db` — если что-то пойдёт не так,
такую копию открывает прежняя версия. Если копию сохранить не удалось, база не меняется и программа сообщает об этом.
Расчёт для существующих сотрудников остаётся тем же: он сверен с версией 1.0 по базе из 113 сотрудников и по набору из
320 синтетических сотрудников (29 февраля, приостановка, доп. отпуск и др.) — отличий нет. После обновления файл
открывает только новая версия (прежняя откажется: «база создана более новой версией»).

**Перенос из Excel.** «Настройки» → «Загрузка из Excel» (или кнопка на пустой «Сводке»): читаются
листы «Сотрудники», «Журнал отпусков» и «Настройки» старой книги. Если в базе уже есть данные,
программа спросит подтверждение и перед заменой сохранит копию.

## Фильтры и печать

На каждой вкладке есть фильтры, которые там нужны:

| Вкладка | Фильтры |
|---------|---------|
| Сводка | поиск, подразделение, состояние (можно несколько; плитки сверху — быстрый выбор), «Отпуск: был / не был / запланирован» за период |
| Сотрудники | то же + статус работы (работают / приостановка / уволены) |
| Периоды | поиск, подразделение, состояние, «Не отгулял / Отгулял» по показанным годам |
| Журнал | поиск, подразделение, статус записи, вид (основной / доп. / без оплаты / по беременности и родам / по уходу за ребёнком), период |
| График | год, поиск, подразделение, статус (по графику / оформлен / в отпуске / использован / не оформлен) |
| Напоминания | поиск, подразделение, срок: все / 14 дней / 1 месяц / конец отпуска / не оформлены |
| Отчёты | подразделение, статус, период |

**Печать выводит ровно то, что сейчас на экране**: те же строки в том же порядке. Нет фильтров — печатается всё;
есть — только отфильтрованное, а в шапке листа написано, какие фильтры стояли («Фильтры: Подразделение: Цех №2 ·
Отпуск: не был в отпуске (01.01.2026 – 31.12.2026) — показано 2 из 17»). Под фильтрами всегда видно «Показано N из M».

Кнопка «Печать» открывает отчёт в браузере (A4 альбомная, шрифт 10 pt, шапки таблиц повторяются на каждой
странице) — дальше `Ctrl/⌘+P` или «Сохранить как PDF», масштаб 100%.

## Горячие клавиши

`⌘/Ctrl + 1…6` — вкладки (Сводка, Сотрудники, Периоды, Журнал, Отчёты, Настройки), `⌘/Ctrl + 7` — График,
`⌘/Ctrl + 8` — Напоминания, `⌘/Ctrl + N` — новый сотрудник.

## Сборка

Нужен Rust (stable). Если он стоит не глобально, `dev-env.sh` подключит локальный тулчейн из каталога
`OTPUSKA_TOOLCHAIN` (внутри `cargo/` и `rustup/`).

```bash
source ./dev-env.sh
cargo run -p otpuska-gui            # запустить
cargo test -p otpuska-core          # тесты расчёта, базы, импорта
packaging/macos/bundle.sh           # dist/Otpuska.app (UNIVERSAL=1 — arm64 + Intel)
packaging/macos/make-dmg.sh         # dist/Otpuska-<версия>-macos.dmg
```

Windows (нужны Rust MSVC и «Build Tools for Visual Studio» с C++):

```powershell
powershell -ExecutionPolicy Bypass -File packaging\windows\build.ps1   # dist\Otpuska\Otpuska.exe
```

Обе сборки делает `.github/workflows/build.yml`: на каждый push — тесты на macOS и Windows и сборки (артефакты),
а тег вида `v1.0.0` публикует релиз с `.dmg`, установщиком `.exe` (Inno Setup) и portable-архивом:

```bash
git tag v1.0.1 && git push origin v1.0.1
```

Замеры и проверки (на копиях баз; открытие новой версией обновляет файл):

```bash
cargo run --release -p otpuska-core --example bench -- копия.db                      # пересчёт всего снимка, мс
OTPUSKA_PERF_DB=копия.db cargo test --release -p otpuska-gui -- --ignored perf_frames --nocapture      # кадр каждого экрана, мс
OTPUSKA_PERF_DB=копия.db cargo test -p otpuska-gui -- --ignored idle_repaint_scan --nocapture          # нет ли кадров «вхолостую»
OTPUSKA_TIMING=1 ./Otpuska                                                           # время запуска и число кадров в консоль
```

Скриншоты всех экранов (egui_kittest, нужна демо-книга для данных):

```bash
OTPUSKA_DEMO_XLSX="../Отпуска. демо с примерами.xlsx" SHOT_DIR=/tmp/shots \
  cargo test -p otpuska-gui -- --ignored screenshots
SHOT_DIR=/tmp/shots cargo test -p otpuska-gui -- --ignored screenshots_new_leave   # новые виды отпусков, график, напоминания
```

Сверка расчёта до и после изменения движка или схемы — на копии базы (открытие новой версией обновляет файл):

```bash
cargo run -p otpuska-core --example baseline -- копия-otpuska.db > до.tsv   # и то же после изменения, затем diff
```

Архитектура и соответствие формул Excel коду — в [ARCHITECTURE.md](ARCHITECTURE.md).
