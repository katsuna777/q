# Отпуска — архитектура

## Стек

| Слой | Выбор | Почему |
|------|-------|--------|
| Ядро | Rust, синхронная библиотека `otpuska-core` | Вся логика — в одном месте и тестируется без окна |
| База | SQLite через `rusqlite` (bundled), WAL | Один файл, без сервера, мгновенный старт, одинаково на macOS и Windows |
| Даты | `chrono` (только `clock`) | `EDATE`/`DATE` ведут себя как в Excel — см. `date.rs` |
| Импорт | `calamine` | Чтение xlsx без Excel |
| GUI | **egui 0.36 + eframe (wgpu)**, `egui_extras` (таблицы), `egui-phosphor`, `rfd` | Тот же стек и тот же вид, что у devbox: чистый Rust, GPU-рендер, без WebView, лёгкий и быстрый |

Данные малы (сотни сотрудников, пара тысяч записей журнала), поэтому **любое изменение сразу пишется в БД и
весь снимок пересчитывается заново** (`Snapshot::build`, доли миллисекунды). Никакого кэша и рассинхрона:
экран всегда рисуется из свежего снимка (`Rc<Snapshot>` в `App`).

## Схема БД (`db.rs`, `PRAGMA user_version = 1`)

```
settings(key, value)                         параметры расчёта; as_of пусто = «сегодня»
departments(id, name UNIQUE, sort)           список подразделений в заданном порядке
employees(id, fio, position, department_id,  department_id → departments, ON DELETE SET NULL
          hire_date, status[work|dismissed|suspended], extra_days, base_days,
          accrual_from, suspend_from, suspend_to, dismiss_date, note)
leaves(id, employee_id, start_date,          employee_id → employees, ON DELETE CASCADE
       base_days, extra_days, note)
```

Даты — ISO-текст `YYYY-MM-DD`, дни — `REAL` (допускаются половинки). В отличие от книги, отпуск привязан к
сотруднику по `id`, а не по тексту ФИО: однофамильцы и переименования ничего не ломают.

## Правила расчёта (`engine.rs`) и где они были в книге

| Книга | Код |
|-------|-----|
| `Сотрудники!V` — начало отсчёта (приём или «Учёт с» + сдвиг на приостановку ТД) | `compute` → `accrual_base` |
| `Y`, `Z`, `AA` — полных лет, начатых и доступных периодов (первый — через N мес.) | `years`, `started`, `available` |
| `AB`/`AC`, `AD`/`AE` — отгуляно и остаток отдельно по основному и доп. отпуску | `taken_*`, `left_*` |
| `AF`…`AJ` — самый ранний период с остатком, крайний срок, дней до срока | `early_period`, `deadline()`, `days_left()` |
| `K` — состояние | `State`, `compute` (порядок проверок тот же) |
| `AL` — ключ сортировки «Сводки» | `State::rank` + `Snapshot::summary_order` |
| `Периоды` — 8 лет подряд, остаток и срок по каждому году | `period`, `period_for_year` |
| `Журнал` — окончание, статус, остаток | `leave_end`, `leave_status` |
| `Отчёты` — ближайшие отпуска и сводка по подразделениям | `Snapshot::upcoming`, `dept_report` |

Проверка: расчёт сверен с пересчётом формул самой книги (движок `formulas` на демо-книге: 18 сотрудников,
144 ячейки «Периодов», счётчики «Сводки») — расхождений нет. Крайние случаи (29 февраля, пороги 90/180 дней,
приостановка, доп. отпуск, записанный как основной) покрыты тестами в `engine.rs`.

## Модули `otpuska-core`

```
date         EDATE/DATE как в Excel, разбор и вывод дат дд.мм.гггг
model        Employee, Leave, Settings, Params, Status
engine       compute, period, Snapshot (сводка, отчёты, предупреждения)
db           SQLite: схема, CRUD, замена всех данных (импорт), копия, проверка файла
config       пути (OTPUSKA_HOME), config.json, ежедневная автокопия, восстановление
xlsx_import  чтение старой книги по заголовкам колонок
filter       фильтры сводки, сотрудников, периодов, журнала и отчётов: одни и те же строки для экрана и печати
print        печатные отчёты (самодостаточный HTML) по готовому списку строк и описанию фильтров
```

## Модули `otpuska-gui`

```
app        состояние, действия над БД, оболочка (боковая панель, шапка, уведомления)
theme      палитры (чёрная тёмная, светлая, 5 акцентов), шрифты Inter / JetBrains Mono
ui         виджеты: кнопки, плашки состояний, карточки, поле даты с календарём, выбор
           сотрудника с поиском, таблицы
platform   открыть файл / показать в папке на macOS, Windows, Linux
views/     summary, employees, employee (карточка), periods, journal, reports, settings
```

**Экран и печать берут строки из одного места** (`filter.rs`: `emp_rows`, `summary_rows`, `period_rows`, `leave_rows`).
Экран сортирует этот список и рисует его, кнопка «Печать» передаёт в `print::*` тот же список вместе с описанием
фильтров — поэтому напечатанное совпадает с показанным; это проверено тестами (`tests.rs`: нажатие «Печать» при
включённых фильтрах).

Модальных окон нет: каждый сценарий — вкладка или карточка в главном окне. Удаление — в два клика
(первый «заряжает» кнопку).
